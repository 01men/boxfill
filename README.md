# boxfill · 装柜数量计算器

集装箱装载方案测算工具。输入柜型与纸箱规格，输出**最优装柜方案**：能装多少箱、怎么摆、
重心在哪，并可导出 PDF 装柜图与报告。

单文件零依赖——`index.html` 双击即用，也可以直接发给装柜工人。

## 快速开始

```sh
open index.html          # macOS，直接在浏览器打开
npm test                 # 跑装箱内核测试（零依赖，用 Node 自带 test runner）
```

## 能力

| 能力 | 说明 |
| --- | --- |
| 柜型 | 20GP / 40GP / 40HQ / 45HQ 预设，也可手填任意柜内尺寸 |
| 混合方向 | 遍历 6 种摆放方向，多策略寻优 + 二次塞缝，把端头缝隙补满 |
| 单一方向 | 所有箱子朝同一方向整齐码放，作为混合方案的对比基线 |
| Top3 对比 | 不同策略各跑一遍完整装柜，取最优 3 个方案并排对比 |
| 3D 装柜图 | 可拖拽旋转 / 滚轮缩放，逐层上色 + 背面剔除 + 画家算法 |
| 分层俯视图 | 按层切换，带毫米网格与坐标标注 |
| 装柜报告 | 一键导出 A4 PDF，含各方向明细、分层汇总、每层俯视图 |
| 约束 | 最大堆码层数、预留装卸间隙、待装数量上限、禁止旋转 |

## 算法

真实装柜是"分层码"的：先铺一层，铺满再往上堆。因此按层求解——

对每一层：

1. 把允许的每种朝向投影到柜底平面，得到若干矩形
2. 用**极大矩形法（MaxRects）**在柜底 2D 装箱
3. 本层高度 = 本层实际放到的箱子里最高的那个
4. 层高累加，直到超出柜内高或超过最大堆码层数

**为什么不用极点 / 扫描线**：那类算法的空闲空间是靠"候选点"间接表达的，一旦候选列表
被裁剪或去重，就可能漏掉仍然合法的空位，把箱子放到已占用区域上——表现就是装出一柜
20,000 箱的荒谬结果。极大矩形法把空闲空间显式维护成互不重叠的矩形列表，每步放置都从
真实空闲区取，放不下就是真的放不下，物理上不会越界。

**多策略寻优**：5 种策略（贴合优先 / 面积优先 / 低层优先 / 高层优先 / 窄长优先）对"这一层
该优先用哪个方向"给出不同答案，从而探索出不同布局。

**二次塞缝**：主装箱靠空闲矩形推进，会剩下一批细长缝。这一遍换个放置偏好（只要浪费面积
最小的方向）再跑一遍，把缝里的箱子补上。

**兜底**：`capacityUpperBound` 给出"体积装满"的物理硬上限。即使算法有 bug，也不会产出
装不下的离谱数字。

## 调用方式

### 1. 浏览器直接打开

双击 `index.html`，填柜型与箱规，点「计算最优装柜方案」。

### 2. URL hash 预填

带参数打开可跳过手填（供上游系统跳转用）：

```
index.html#len=600&wid=400&hei=350&wt=15&qty=1360&type=40HQ
```

| 参数 | 含义 |
| --- | --- |
| `len` / `wid` / `hei` | 纸箱长 / 宽 / 高（mm） |
| `wt` | 单箱毛重（kg） |
| `qty` | 待装数量 |
| `type` | 柜型：`20GP` / `40GP` / `40HQ` / `45HQ` |
| `cbm` | 总体积（CBM）。没给 `qty` 时按单箱体积反推件数 |

### 3. 脚本调用

页面底部把工具挂到了 `window.ContainerLoader` 上：

```js
const plan = ContainerLoader.set({
  ctype: '40HQ',
  bL: 600, bW: 400, bH: 350,
  bWt: 15, gap: 0, maxLayer: 0, qty: 0,
  allowRotate: true, useSecondPass: true,
})

console.log(plan.boxes, plan.util, plan.layerCount, plan.cog)
```

`ContainerLoader.solve()` 只算不渲染，返回 `{ plans, single, opts }`。

`plan.layers` 里每层是 `{ z, h, items }`，每个 item 是 `{ x, y, di, dz }`——
`di` 是方向索引，对应下表的轴序：

| 索引 | 方向 | 占位轴 |
| --- | --- | --- |
| 0 | 正常堆放 | L×W×H |
| 1 | 长面侧放 | L×H×W |
| 2 | 宽面侧放 | W×L×H |
| 3 | 倒面侧放 | W×H×L |
| 4 | 横放 | H×L×W |
| 5 | 卧放 | H×W×L |

## 测试

装箱内核是这个项目里最容易出错、后果也最直接的算法——一旦结果出现重叠或越界，单证员就会
拿着一张装不下的方案去装柜。所以测试从 `index.html` 的 `<script>` 里抽出纯逻辑部分（截到
「渲染」分节之前，无 DOM 依赖），在 Node 下直接跑：

```sh
npm test
```

11 条用例覆盖 7 组柜型 / 箱规组合，断言三条硬约束：

1. 任意两个箱子在柜底投影上不重叠
2. 所有箱子都在柜内尺寸内
3. 层高累加不超过柜内高，且不超过最大堆码层数

外加：箱数落在物理容量区间内、混合方向不劣于单一方向基线、堆码层数 / 待装数量上限生效、
禁止旋转时不出现倒置方向、纸箱超柜时给出明确错误、各方向用量之和等于总箱数。

> 抽取内核依赖 `index.html` 里那条「渲染」分节注释分隔符。改动 HTML 结构时如果测试报
> `装箱内核抽取失败`，说明分隔符被挪动了，需要同步更新 `tests/packing.test.mjs` 里的
> `loadKernel()`。

## 注意

本工具算的是**几何可行**的装箱方案，不含以下约束，实际装柜前请人工复核：

- 承重限制（柜体最大载重、单箱堆码压力、重心偏移对安全的影响）
- 易碎品 / 重货在下、重货在下等业务规则
- 目的国海关对木质包装（IPPC）的处理
- 实际装柜顺序与示意图的差异

仓库私有，仅供内部使用。
